# 计算机网络基础

## IPv4、CIDR、子网与路由

IPv4 地址是配置在网络接口上的逻辑地址，用于在网络层标识通信端点。它不是设备永久不变的身份：一台电脑可以同时拥有 Wi-Fi、回环和 VPN 虚拟接口，每个接口都可以有自己的地址

IPv4 地址共 32 位，通常分成 4 组 8 位并写成点分十进制，每组的取值范围是 `0～255`：

```plain
11000000.10101000.00000001.00001010
     192.     168.       1.      10
```

### 网络接口

常见的网络接口包括：

- `en0`：常见的 Wi-Fi 或以太网接口名称，实际名称以系统配置为准
- `lo0`：回环接口，发往回环地址的数据不会离开本机
- `utunN`：VPN 或代理软件常用的虚拟隧道接口

发送数据时，操作系统不仅要选择下一跳，还要选择从哪个接口发出，因此“本机 IP”可能不止一个。例如 `192.168.1.10/24` 可以是 `en0` 的 IP 地址，`127.0.0.1` 则是本机回环地址，两者都属于本机，但作用范围不同

### CIDR 与子网掩码

CIDR（Classless Inter-Domain Routing，无类别域间路由）使用 `地址/前缀长度` 描述一个地址块，例如 `192.168.1.0/24`。`/24` 表示 IP 地址的前 24 位属于网络前缀；对应的子网掩码前 24 位为 `1`、后 8 位为 `0`

```plain
前缀长度： /24
二进制：   11111111.11111111.11111111.00000000
子网掩码： 255.255.255.0
```

常见前缀长度与子网掩码：

| 前缀长度 | 子网掩码          | 地址总数        |
| -------- | ----------------- | --------------- |
| `/16`    | `255.255.0.0`     | `2^16 = 65,536` |
| `/20`    | `255.255.240.0`   | `2^12 = 4,096`  |
| `/24`    | `255.255.255.0`   | `2^8 = 256`     |
| `/25`    | `255.255.255.128` | `2^7 = 128`     |

### 网络前缀、网络地址、主机地址与广播地址

子网掩码用于区分 IP 地址中的网络部分和主机部分：

- 网络前缀：由 `/n` 指定的前 `n` 位
- 网络地址：保留网络前缀，并把所有主机位设为 `0`
- 定向广播地址：在支持广播的普通 IPv4 子网中，把所有主机位设为 `1`
- 普通主机地址：位于网络地址和广播地址之间，可配置给具体接口
- 受限广播地址：`255.255.255.255`，只用于当前本地网络

例如 `192.168.1.10/24`：

```plain
IP 地址：    192.168.1.10
CIDR：      192.168.1.0/24
网络地址：   192.168.1.0
广播地址：   192.168.1.255
```

> 网络地址和广播地址不可分配给普通主机是常规广播子网中的规则；`/31` 点对点链路和 `/32` 单地址路由存在不同语义

### 私网、公网与常见特殊地址

CIDR 只描述地址块边界，不决定地址用途。判断一个地址是否属于私网、回环、组播或其他特殊用途，需要检查它是否落入相应的保留前缀

常见 IPv4 特殊用途地址：

| 地址范围                                            | 用途                                            |
| --------------------------------------------------- | ----------------------------------------------- |
| `0.0.0.0/8`                                         | “本网络”等特殊用途；`0.0.0.0/32` 表示未指定地址 |
| `10.0.0.0/8`                                        | RFC 1918 私网                                   |
| `100.64.0.0/10`                                     | 共享地址空间，常用于运营商级 NAT                |
| `127.0.0.0/8`                                       | 本机回环                                        |
| `169.254.0.0/16`                                    | IPv4 链路本地地址                               |
| `172.16.0.0/12`                                     | RFC 1918 私网                                   |
| `192.168.0.0/16`                                    | RFC 1918 私网                                   |
| `192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24` | 文档示例地址                                    |
| `198.18.0.0/15`                                     | 网络设备基准测试                                |
| `224.0.0.0/4`                                       | IPv4 组播                                       |
| `240.0.0.0/4`                                       | 保留范围，其中存在更具体的特殊地址定义          |
| `255.255.255.255/32`                                | 受限广播                                        |

RFC 1918 私网包括：

```plain
10.0.0.0      ～ 10.255.255.255
172.16.0.0    ～ 172.31.255.255
192.168.0.0   ～ 192.168.255.255
```

私网地址可以在不同组织内部重复使用，不作为普通全球单播地址在公网传播。私网设备通常通过边界网关的 NAT 或代理访问外部服务，但私网地址本身不代表安全，NAT 也不能替代访问控制

“非私网”不等于“公网可达”：还要排除回环、链路本地、共享、文档、组播等特殊范围。即使一个地址可作为全球单播地址使用，也要分别确认它是否已经分配、当前是否存在公网路由，以及目标服务是否允许访问

组播（multicast）允许一个发送者向加入特定组的多个接收者发送数据；IPv4 组播范围是 `224.0.0.0～239.255.255.255`

### 路由表、最长前缀匹配与默认网关

操作系统发送 IP 数据包前会查询路由表。路由表中的一条记录通常描述：

- 目标网络前缀：这条规则覆盖哪些目的 IP
- 下一跳网关：数据包接下来交给哪台路由器；直连路由可以没有网关
- 出口接口：从哪个物理或虚拟接口发出
- 优先信息：当多条路线同样具体时，系统还可能根据度量值和策略选择

示例路由表：

| 目标网络前缀     | 下一跳        | 接口    | 含义         |
| ---------------- | ------------- | ------- | ------------ |
| `192.168.1.0/24` | 直连          | `en0`   | 本地子网     |
| `10.0.0.0/8`     | VPN 网关      | `utun4` | 特定网络路由 |
| `0.0.0.0/0`      | `192.168.1.1` | `en0`   | 默认路由     |

一个目标可能同时匹配多条路由。系统先选择前缀长度最长、覆盖范围最具体的路由，这称为最长前缀匹配；只有具体程度相同时，才继续比较系统的度量值或策略

默认网关是默认路由选择的下一跳路由器，不是互联网本身，也不是最终服务器。目标不在直连子网且没有其他更具体的路由时，系统才把数据包交给默认网关

### 逐跳转发与 TTL

以浏览器访问远端服务器为例：

```plain
浏览器通过 DNS 获得服务器 IP
  ↓
操作系统查询路由表并选择出口接口和下一跳
  ├── 目标命中直连路由：从本地接口发往目标
  └── 目标位于远端网络：先交给特定网关或默认网关
        ↓
      每台路由器查询自己的路由表，继续选择下一跳
        ↓
      到达最终服务器
```

在没有 NAT 或隧道封装等机制介入时，IP 数据包中的最终目的 IP 仍然是服务器地址，网关只是当前这一跳的接收者。如何在局域网中找到下一跳的链路层地址由 ARP 完成

IPv4 头中的 TTL（Time to Live）用于限制数据包可以经过的路由跳数。路由器转发数据包时会减少 TTL，减到 0 时丢弃数据包，从而避免错误路由导致数据包无限循环。TTL 是 IP 转发机制，不是 DNS 记录的缓存 TTL

## 以太网与 MAC 地址

IP 地址在网络层标识通信端点，MAC 地址则用于标识当前链路上的网络接口。经典以太网 MAC 地址通常是 48 位，写成 6 组十六进制数，例如 `02:00:00:00:00:01`

一台设备可以有多个网络接口，每个接口可以使用不同的 MAC 地址。操作系统还可能针对不同 Wi-Fi 网络使用私有地址，因此 MAC 地址不是设备永久不变的身份

IP 数据包通过以太网传输时，会被封装在以太网帧的数据部分。帧中包含当前链路使用的源 MAC 和目的 MAC；路由器转发 IP 数据包时，会针对下一段链路重新封装帧，因此 MAC 地址不会像最终目的 IP 一样贯穿整条路由路径

以太网广播地址是 `ff:ff:ff:ff:ff:ff`。交换机通常把广播帧转发到同一广播域内的其他端口，路由器不会默认把这种链路层广播转发到其他子网

路由表、ARP 缓存和交换机转发表解决不同问题：

| 数据结构     | 典型映射                          | 主要使用者   |
| ------------ | --------------------------------- | ------------ |
| 路由表       | 目的网络前缀 → 下一跳和出口接口   | 主机、路由器 |
| ARP 缓存     | 本地链路上的 IPv4 地址 → MAC 地址 | 主机、路由器 |
| 交换机转发表 | MAC 地址 → 交换机端口             | 交换机       |

## ARP 地址解析

ARP（Address Resolution Protocol，地址解析协议）用于在支持 ARP 的本地链路上，把下一跳 IPv4 地址解析为链路层地址。它解析的是路由表选出的下一跳，不一定是 IP 数据包的最终目标

当 ARP 缓存中没有可用映射时，正常流程是：

1. 操作系统先查询路由表，确定出口接口和下一跳 IPv4 地址
2. 主机以链路层广播发送 ARP Request，询问谁拥有该 IPv4 地址
3. 拥有该地址的接口通常直接向请求方发送 ARP Reply
4. 请求方把 IPv4 与 MAC 的映射暂时写入 ARP 缓存
5. 主机使用得到的目的 MAC 构造链路层帧

ARP 不是所有网络接口通用的寻址机制：IPv6 使用 Neighbor Discovery，回环、隧道和某些点对点接口也不一定需要以太网 ARP

## DHCP 动态配置

DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）用于向客户端提供网络配置。客户端通常可以获得：

- IPv4 地址
- 子网掩码
- Router，也就是供客户端使用的路由器列表
- DNS 服务器
- 地址租期

客户端首次申请新地址时，典型流程称为 DORA：

| 消息         | 方向            | 作用                         |
| ------------ | --------------- | ---------------------------- |
| DHCPDISCOVER | 客户端 → 服务器 | 寻找可用的 DHCP 服务器       |
| DHCPOFFER    | 服务器 → 客户端 | 提供地址和其他配置           |
| DHCPREQUEST  | 客户端 → 服务器 | 选择并请求一份配置           |
| DHCPACK      | 服务器 → 客户端 | 确认租约，客户端开始使用配置 |

尚未获得正常 IPv4 地址的客户端仍可以寻找服务器。典型的 DHCPDISCOVER 使用客户端 UDP 端口 68 向服务器端口 67 发送，源 IP 可以是 `0.0.0.0`，目的 IP 可以是受限广播地址 `255.255.255.255`，链路层目的地址则是广播地址

广播只在当前广播域内传播，但 DHCP Relay 可以把客户端请求转交给其他网络中的服务器，因此 DHCP 服务器不一定与客户端位于同一个子网

DORA 是首次分配新地址的典型流程，不代表每次 DHCP 通信都固定经历四步。客户端使用已有地址重新初始化、续租或重新绑定时，可能直接发送 DHCPREQUEST 并接收 DHCPACK；续租初期还可能向原服务器单播请求

## 从接入网络到发送数据

```plain
设备接入本地网络
  ↓
DHCP 提供 IP、子网掩码、路由器、DNS 和租期
  ↓
应用通过 DNS 等方式获得目标服务器 IP
  ↓
操作系统查询路由表，选择出口接口和下一跳 IPv4
  ↓
在使用 ARP 的本地链路上查询下一跳对应的 MAC
  ↓
使用下一跳 MAC 构造并发送链路层帧
  ↓
目标主机接收，或路由器解封装后继续逐跳转发
```

## 终端命令

```bash
# 查看当前默认路由
route -n get default

# 查看指定接口的 IPv4 地址
ipconfig getifaddr INTERFACE

# 查看指定接口上缓存的网关 ARP 记录
arp -n -i INTERFACE GATEWAY_IP

# 查看客户端接受的 DHCP/BOOTP 报文
ipconfig getpacket INTERFACE

# 分别查看 DHCP 提供的配置项
ipconfig getoption INTERFACE subnet_mask
ipconfig getoption INTERFACE router
ipconfig getoption INTERFACE domain_name_server
ipconfig getoption INTERFACE lease_time
```
