## 01 · Libghostty：终端能力成为可稳定链接的库

**2026-11-06 · 开源 / 开发工具 · libghostty-vt 1.0 稳定版，MIT 许可**

Mitchell Hashimoto 宣布 `libghostty-vt` 1.0 发布。这是从 Ghostty 核心抽取的终端模拟 C 库，拥有独立于桌面应用的发布周期；此次里程碑是库与 C ABI 的稳定承诺。ABI 可以理解为已经编译的程序与库之间的二进制接口，关系到替换动态库之后，已有程序是否还能正确调用。[作者原始公告](https://mitchellh.com/writing/libghostty-1-0)

项目用不透明句柄、可扩展结构和版本化符号组织接口，并通过 CI 检查兼容性。发布还提供签名源码包和依赖包，支持离线构建，配套标准库文件、头文件与构建系统配置。公告将“构建并运行测试的平台”和“目前只检查构建的平台”分别列出。

**为什么值得关注：** 编辑器、终端应用和命令行界面都可能需要解释终端控制序列。共享这部分实现，可以让多个产品复用修复与协议支持；稳定的二进制接口则降低了发行版打包和长期集成的成本。

**Codex 建议：** 先读 ABI 与打包部分，再看性能宣传。这次发布的价值不只在速度，也在于调用方能依赖哪些兼容约定。需要嵌入终端时，还应确认目标平台的测试级别，以及自己需要补齐的界面与交互层；库稳定并不意味着整套应用已经替你完成。

## 02 · Agent Registry：技能包也有不可变版本和扫描记录

**2026-11-06 · AI / 安全 / 云基础设施 · 独立 Skills 正式可用，客户管理密钥仍为 Preview**

Google Cloud 宣布 Agent Registry 的独立技能资源正式可用，可注册、搜索和管理 `Skill`、不可变的 `SkillRevision` 包及已验证发布者信息。同日更新加入技能安全扫描与组织策略管理；用于技能载荷静态加密的客户管理密钥（CMEK）仍标为 Preview，不能随主功能一并视为正式发布。[版本更新记录](https://docs.cloud.google.com/agent-registry/release-notes)

扫描文档说明，系统检查 `SKILL.md`、脚本和支持资源，关注数据外传、暴露凭据与提示注入等风险。默认阻塞策略会限制存在发现的版本下载，并阻止将有发现或仍待扫描的版本设为默认。开启扫描只影响之后创建的版本，不会自动追溯扫描已有版本。[扫描机制与限制](https://docs.cloud.google.com/agent-registry/scan-skills)

**为什么值得关注：** 技能包可以包含指令和可执行脚本，实际影响往往超过一段提示词。把版本、来源、扫描结果与分发规则关联起来，有助于回答“Agent 当时加载了哪一份内容”，也让更新与回退有明确对象。

**Codex 观察：** 扫描使用大模型，官方明确提示可能误报、漏报或产生不准确的细节。`SUCCEEDED` 表示扫描完成，还要检查发现列表；没有发现也不是安全证明。不可变版本方便追踪，运行时权限、工具范围和人工核查仍是独立环节。

## 03 · Copilot 审查：设置与结果开始更适合程序化管理

**2026-11-06 · AI / 开发平台 · 更新已提供给公告列出的 Copilot 订阅计划**

GitHub 扩展 Copilot code review 的 REST 与 GraphQL 接口，可管理从企业到仓库的审查设置，并通过明确字段识别 Copilot 的审查与评论。结果还可附带审查强度，以及 Copilot 报告使用的技能、MCP 服务和自定义指令来源。Balanced 审查调整为三个审查模型，再由另一个模型汇总发现。[GitHub 原始更新日志](https://github.blog/changelog/2026-11-06-copilot-code-review-api-management-and-review-overview-updates/)

接入权限存在层级差异：企业和组织设置端点目前不支持 GitHub Apps 或细粒度个人令牌；仓库设置端点支持两者，但读取、修改分别需要对应的 Administration 权限。企业管理的设置不能由组织覆盖。此次更新还把跳过与内容排除文件汇总到“未审查文件”区域。

**为什么值得关注：** 当团队把 AI 审查接入内部平台，除了发起一次请求，还需要知道配置由谁控制、结果用了哪些输入、哪些文件没有覆盖。可查询的设置和结构化结果，能帮助自动化流程保留这些上下文。

**Codex 建议：** 可以先看设置层级与认证支持，再考虑批量管理。模型数量增加是实现变化，不能直接当作准确率提升的独立证据；评论标注的来源也不等于完整、可重放的推理过程。评估审查价值时，仍应结合具体发现、误报和未覆盖文件。

关心基础组件设计，先读 **Libghostty 的兼容与打包策略**。维护 Agent 工具链，可以看 **技能版本与扫描状态如何绑定**。管理团队审查流程，则重点关注 **Copilot API 的权限层级和未审查文件信息**：这些细节比单次演示更接近持续使用时需要解决的问题。
