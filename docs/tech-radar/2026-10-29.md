## 01 · GitHub Agentic Workflows：把推理任务纳入 Actions

**2026-10-28 · AI / 开发工具 · 正式可用，默认 Copilot 引擎需要相应许可证**

GitHub 宣布 Agentic Workflows 正式可用。开发者用 Markdown 描述问题分类、CI 故障分析、文档维护等任务，再将其编译成标准 Actions YAML；运行时沿用既有 runner 分组与策略，也可选择其他编码 Agent。公告列出的新增能力包括 ARC 自托管 runner 支持、模型路由，以及不再标为实验性的预算预测命令 `gh aw forecast`。[正式发布公告](https://github.blog/changelog/2026-10-28-github-agentic-workflows-generally-available/)

这里值得关注的是执行边界：Agent 默认只读，在沙箱与网络防火墙后运行；写入通过声明的 safe outputs 处理，另有威胁检测任务检查拟议变更。官方文档将这些输出组织成可配置动作，例如创建 issue 或提出 PR，而非给任务一个不受限制的写入入口。[Safe Outputs 文档](https://github.github.com/gh-aw/reference/safe-outputs/)

**为什么值得关注：** 团队已有定时任务、权限规则和运行日志，推理型自动化可以接入同一套管理流程。比如 CI 失败后，工作流先读取日志并归纳原因，再按允许的输出提交结果；维护者能同时检查任务定义、运行记录和产物。

**Codex 建议：** 可以先读任务定义与输出配置的对应关系。正式可用说明产品进入新的支持阶段，任务结论仍需验证；默认只读、输出检查和权限限制各自解决不同问题。预算预测也只是规划依据，实际费用取决于运行频次、任务复杂度与模型选择。

## 02 · Zephyr 4.5：固件清单开始说明“怎样构建出来”

**2026-10-28 · 开源 / 嵌入式系统 · 4.5 正式发布，多媒体管线仍为实验性**

Zephyr 4.5 新增 Infineon TriCore 和 Qualcomm Hexagon 架构支持，并扩展网络能力。它还引入实验性的多媒体管线 mpipe，用来源、变换和输出模块组织媒体数据流。公告提醒，新架构所需的部分模拟器或工具链尚未随 Zephyr SDK 一起提供，使用前需按板级文档配置。[项目发布介绍](https://www.zephyrproject.org/zephyr-rtos-4-5-now-available-two-new-architectures-multimedia-pipelines-sboms-and-more/)

更值得细读的是软件物料清单（SBOM）。`west spdx` 新增 SPDX 3.0 输出，借助 CMake 的文件 API 记录构建工具、编译参数，以及源文件到库和最终产物的关系。默认格式仍为 SPDX 2.3，需要显式选择 3.0；开发文档进一步解释了 Build profile 如何把输入、输出和工具连接起来。[构建溯源文档](https://docs.zephyrproject.org/latest/develop/west/zephyr-cmds.html#build-profile-spdx-3-0)

**为什么值得关注：** 同一份源码经过不同配置和工具链，可以得到不同固件。遇到只影响特定编译条件的问题时，单看依赖名和版本不够；保存实际构建关系，有助于找到哪些产物需要进一步检查，也便于追踪一个二进制的来源。

**Codex 观察：** 先看 SBOM 的产物示例，比逐项记新功能更容易理解其用途。清单是调查线索，不能独自证明固件没有漏洞。对 mpipe 演示也应保留版本边界：作者说明部分视频与显示模块仍在评审，演示里的神经网络实际运行在本地 GPU，不能概括为正式版已在微控制器上完成全部流程。

## 03 · NVS-03：区域导航系统继续更新星载能力

**2026-10-28 任务页面 · 航天 / 导航基础设施 · 发射计划说明，未据此确认已入轨或提供服务**

印度空间研究组织 ISRO 公布 GSLV-F18/NVS-03 任务信息：计划使用 GSLV 将 NVS-03 送入地球同步转移轨道。这是其下一代区域导航卫星系列的第三颗，目标是延续 IRNSS 系列导航服务。卫星同时搭载印度自主研制与外购原子钟，并在既有 L5、S 波段之外加入 L1 信号。[ISRO 原始任务页面](https://www.isro.gov.in/Mission_GSLVF18.html)

**为什么值得关注：** 导航基础设施的升级包含时钟和无线信号两部分。稳定的时间基准支撑测距，接收机则需要支持相应信号才能使用服务。对软件开发者而言，这是一个从基础设施理解定位能力的入口：应用显示一个坐标，背后涉及卫星、接收硬件和处理软件共同工作。

**Codex 观察：** 官方页面描述的目标覆盖范围是印度陆地及边界外约 1,500 公里区域。它使用计划发射的表述，因此本期不将其写成发射成功或新服务已上线。后续值得跟踪的是实际入轨、在轨验证和服务状态；单独增加一个频段，也不能推出所有手机立即获得更高精度。
