## 01 · Infinity：Agent 等待工具时，可以先结束当前执行

**2026-10-23 · AI / 基础设施 · Apache 2.0 开源，早期研究版本**

AWS 与加州大学伯克利分校合作的 Hydro 项目发布 Infinity。它把 Agent 的一次执行拆成有限步骤：加载会话、调用模型、保存输出、派发工具，然后结束当前执行；工具结果到达消息队列后，再恢复下一步。这样，等待构建或外部事件时，不需要一直保留运行中的 Agent 调用。[AWS 原始介绍](https://aws.amazon.com/blogs/opensource/introducing-infinity-a-runtime-for-extreme-agent-concurrency/)

项目提供 Rust 框架，空闲 Agent 主要保留会话数据。[项目文档](https://infinity.hydro.run/) 展示了异步工具与事件机制。公告中的“8 GB 可容纳约 7.5 万个 Agent”需要连同实验条件阅读：团队在 AMD EPYC 单线程上使用模拟模型和内存存储，测得每个空闲 Agent 约占 100 KB，再推算容量；这不是树莓派同时运行数万个模型的实测。

**为什么值得关注：** 长任务的资源消耗包含大量等待时间。把等待状态存下来、收到事件再继续，可以让持续几天的工作流更自然地接入按次执行的基础设施，也让“执行多久”和“任务持续多久”分开处理。

**Codex 观察：** 最值得看的是挂起与恢复的设计。官方仍把事件交错对模型决策的影响、调度策略和事件真实性列为开放问题。内存容量也不能直接换算成真实任务吞吐量，后者还取决于模型服务、工具与存储。

## 02 · OBS Studio 33.0：浏览器内容与插件体系一起更新

**2026-10-23（GitHub 发布记录）· 开源 / 创作工具 · 33.0.0 正式版**

OBS Studio 发布 33.0.0，将浏览器源和嵌入式面板使用的 Chromium Embedded Framework（CEF）从 127 更新到 150，并重构插件加载。预览中的素材吸附增加视觉提示，隐藏素材也不再参与吸附。发布说明同时列出 Ubuntu 24.04 停止支持等兼容性变化。[官方发布说明](https://github.com/obsproject/obs-studio/releases/tag/33.0.0)

插件迁移需要分平台看。官方指引详细说明 Windows 的新目录结构，旧位置会在过渡期继续加载，到 OBS 34.0 停止支持；macOS 插件位置没有变化，Linux 说明目前仍待补充。对于依赖复杂的插件，官方建议遵循插件作者指引，不宜直接搬动文件。[插件迁移说明](https://obsproject.com/kb/legacy-plugin-locations)

**为什么值得关注：** OBS 的浏览器源可以承载用网页制作的字幕、数据面板和互动内容。浏览器内核更新会影响这些内容的运行环境，而插件目录调整则影响扩展能否被发现和加载。两类变化都值得放进现有场景的升级检查中。

**Codex 建议：** 已有录制或直播配置，可以先确认常用插件的适配情况，再检查浏览器源、音频与画面组合。此次发布有明确的兼容性过渡安排，不应把正式版理解为所有第三方扩展都已完成迁移。

## 03 · 近期补读：OCA Harness 为芯粒提供可复用的公共模块

**2026-10-22 · 硬件 / 开源 · Beta 已开放，完整版本目标为 2027 年 1 月**

Tenstorrent 发布 Open Chiplet Atlas（OCA）Harness 开源 Beta，提供安全启动、系统管理、调试测试和芯粒互联等参考实现。芯粒可以理解为组合成系统的多个硅模块；Harness 处理这些模块共同需要的基础功能，让设计团队更集中地开发自己的计算或加速逻辑。[原始公告](https://tenstorrent.com/newsroom/tenstorrent-releases-open-source-beta-of-the-oca-harness)

项目包含描述硬件电路的 RTL，以及支持提前开发固件的 C++/SystemC 虚拟平台。仓库入口分别列出硬件设计、互联桥、虚拟模型和启动清单工具；主体代码采用 Apache 2.0，文档与图片另用 CC BY 4.0。公告把本次版本定位于早期使用者和集成者，完整发布仍是后续目标。[代码与文档入口](https://github.com/tenstorrent/tt-oca-harness)

**为什么值得关注：** 开放硬件的价值也包括复用那些每个设计都要实现的启动、管理和调试功能。公开参考实现，让不同团队有机会围绕共同接口开展集成，而不仅是阅读一份规范。

**Codex 观察：** 可以先看各模块的职责，以及虚拟平台能验证哪些流程。源码开放与仿真能力提供了协作起点；真实芯粒之间的互操作、物理连接和量产表现，仍需要后续硬件验证。降低成本是厂商提出的预期收益，本文没有独立测量。
