# MySQL

## cli

```bash
mysql -h <host> -P <port> -u <username> -p
```

## MySQL 执行流程

MySQL 的框架分为两层：

- server 层：负责建立连接、解析和执行 SQL，主要包括连接器、查询缓存、解析器、优化器和执行器等组件
- 存储引擎层：负责数据的存储和检索，不同的存储引擎提供不同的功能和特性，支持 InnoDB（MySQL 5.5+ 默认存储引擎）、MyISAM、Memory 等多种存储引擎

### 连接器

- 基于 TCP 协议传输：三次握手建立连接，四次挥手断开连接
- 身份认证：用户名、密码、主机权限
- 权限读取：从 mysql.user 表读取权限信息，后续操作基于此权限进行
- 维持连接：最大空闲时间（wait_timeout）默认是 8h
- 使用长连接减少建立连接和断开连接的开销，但会导致内存增长
  > - 定时断开连接
  > - 客户端使用 `mysql_reset_connection()` 重置连接状态

### 查询缓存

对于频繁更新的表，查询缓存命中率很低，MySQL 8.0 移除 server 层的查询缓存

> 使用第三方缓存（如 Redis）或存储引擎层的缓存（如 InnoDB Buffer Pool）来提高查询性能

### 解析器

- 词法分析：将 SQL 语句分解成一个个 token
- 语法分析：检查 SQL 语句是否有语法错误，构建抽象语法树

### 执行 SQL

#### 预处理器

- 检查 SQL 语句中的表或字段是否存在
- 将 `SELECT *` 中的 `*` 替换成具体的字段列表

#### 优化器

制定执行计划，包括索引选择、连接顺序、执行策略等，使用 `EXPLAIN <sql>` 查看执行计划

> `system > const > eq_ref > ref > range > index > ALL`

#### 执行器

根据执行计划执行 SQL 语句，调用存储引擎 API，返回结果

## InnoDB 存储结构

```plain
表空间（Tablespace）
  └─ 段（Segment）            ← 一个索引（聚簇索引 / 二级索引）对应两个段
       └─ 区（Extent）        ← 1MB，每次磁盘分配的单位，包含 64 个连续的页
            └─ 页（Page）     ← 16KB，InnoDB 读写的最小单位
                 └─ 行（Row） ← 实际数据存放
```

- 表空间：段的集合
- 段：区的集合
  - 索引段：存储 B+ 树的非叶节点（索引节点）的区的集合
  - 数据段：存储 B+ 树的叶节点（数据节点）的区的集合
  - 回滚段：存储事务的 undo log 的区的集合，InnoDB 使用 read view + undo log 实现 MVCC 多版本并发控制
- 区：页的集合
  - 区是 InnoDB 分配存储空间的基本单位
  - InnoDB 使用 B+ 树，B+ 树的每一层使用双向链表，如果以页为单位分配存储空间，则双向链表中相邻的两个页的物理地址不连续，导致查询磁盘时有大量随机 I/O，以区为单位分配存储空间，则双向链表中相邻的两个页的物理地址连续，查询磁盘时是顺序 I/O，范围查询（扫描叶节点）时性能很高
  - 默认区大小是 1MB，对于 16KB 的页，1 个区分为 64 个页
- 页：行的集合
  - 页是 InnoDB 读写数据的基本单位
  - 如果以行为单位读写数据，1 次 I/O 操作只能处理 1 行数据，以页为单位读写数据，默认页大小是 16KB 的连续存储空间，1 次 I/O 操作可以处理至少 16KB 的数据
  - 页分为：数据页、undo 日志页、redo 日志页、溢出页；表中的记录存储到数据页

### 行格式

- 不紧凑的行格式：redundant
- 紧凑的行格式：compact、dynamic（默认）、compressed
  - compact 行格式发生行溢出时，只存储该列的部分数据，剩余数据存储到溢出页中
  - dynamic 和 compressed 行格式发生行溢出时，不存储该列的部分数据，数据完全存储到溢出页中

compact 行格式的一条记录分为「记录的额外信息」和「记录的真实数据」

**记录的额外信息：变长字段的长度列表、null 值列表、记录头信息**

- 变长字段的长度列表
  - 只有表中存在变长字段时，才有变长字段的长度列表（例如 VARCHAR）
  - 变长字段的长度列表按照列的顺序逆序存储，使记录头中靠近真实数据的长度信息可以按相反方向依次解析
- null 值列表
  - 只有表中存在 NULLABLE 字段时，才有 null 值列表；字段都是 NOT NULL 时，没有 null 值列表
  - null 值列表按照列的顺序逆序存储
  - compact 行格式使用 null 值列表标识为 null 的列，null 值不会存储到记录的真实数据
    > 二进制值为 1 时，表示该列的值为 null；二进制值为 0 时，表示该列的值不为 null
- 记录头信息（5 字节）
  - delete_mask：标识该条记录是否被删除；执行 DELETE 删除时，不会立刻删除记录，而是将该条记录的 delete_mask 设置为 1
  - next_record：下一条记录的物理地址，指向下一条记录的「记录头信息」和「真实数据」之间的位置
  - record_type：记录类型，0 表示普通记录，1 表示 B+ 树非叶子节点，2 表示最小记录，3 表示最大记录

**记录的真实数据**

- row_id：非必需；InnoDB 优先使用主键作为聚簇索引。没有主键时，会选择第一个所有列均为 `NOT NULL` 的唯一索引；如果两者都不存在，才为记录生成 6 字节的隐藏 row ID
- trx_id 必需；创建/更新该条记录的事务 id，长度 6 个字节
- roll_pointer 必需；指向该条记录上个版本（写入到 undo log）的指针，长度 7 个字节
- 列 1、列 2、...

::: tip MySQL 字段长度限制
MySQL 规定，除了 TEXT、BLOB 类型的字段，其他所有字段（不包含隐藏字段和记录头信息）占用的字节长度之和不能超过 65535 字节，即：所有字段的总长度 + 变长字段的长度列表占用的字节数 + null 值列表占用的字节数 <= 65535
:::
